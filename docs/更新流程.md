# Rebased 更新流程

本文只讲一件事：如何把新版本做成**自签名**安装包、放到更新服务器、让已安装的 Rebased 启动时自动检查并**静默安装**。

请严格按顺序做。漏改版本号、只上传安装包不改清单、或清单版本不高于用户当前版本，用户都不会看到更新。

---

## 1. 整体流程（先看这一张图）

```
git commit（提交标题就是更新日志）
    ↓
运行 scripts\update.ps1（改版本、打包、用自签名证书签名、上传）
    ↓
用户打开 Rebased
    ↓
程序请求 http://111.230.247.111/rebased/latest.json
    ↓
清单里的 version > 本地 version ？
    ├─ 否：不提示
    └─ 是：右下角提示「正在后台下载并静默安装」
            ↓
        下载 latest.json 里的 url 安装包（只接受 *-setup.exe）
            ↓
        校验 sha256（必填，缺失或不一致都拒绝安装）
            ↓
        校验 Authenticode 签名：未被篡改 + 证书指纹等于客户端内置指纹
            ↓
        以 /S /R /UPDATE 静默运行安装包，客户端 1.5 秒后自行退出
            ↓
        安装完成后安装程序自动重新打开 Rebased
```

开发模式（`npm run tauri dev`）只提示不自动安装，避免把正式安装目录覆盖掉。

客户端**只会访问 HTTP**，不会用 SSH，也不会带服务器密码。

## 3. 版本号规则

程序用 `src-tauri/Cargo.toml` 里的 `version` 判断自己是不是旧版。

比较规则：把 `x.y.z` 拆成三段数字，**清单 version 必须大于本地 version** 才会提示更新。

例如：

- 本地 `0.1.0`，清单 `0.1.0` → 不更新
- 本地 `0.1.0`，清单 `0.1.1` → 提示更新
- 本地 `0.1.1`，清单 `0.1.0` → 不更新

发版时脚本默认把 `tauri.conf.json` 的版本号末位 +1，用最近一条 git 提交标题作为更新日志，追加到 `update.txt` 末尾，并把版本号同步到：

1. `src-tauri/Cargo.toml`
2. `src-tauri/tauri.conf.json`
3. `package.json`

## 4. 开发机发布前准备（只需做一次）

### 4.1 确认本机有这些工具

- Node.js、Rust、Tauri CLI（能执行 `npm run tauri build`）
- Python 3
- Python 包：`paramiko`（没有就执行 `pip install paramiko`）

### 4.2 确认发布密码文件存在

打开 `scripts/.update-server.env`，内容必须是：

```env
UPDATE_HOST=111.230.247.111
UPDATE_USER=root
UPDATE_PASS=<服务器登录密码>
UPDATE_DIR=/usr/share/nginx/html/rebased
```

没有这个文件时，可复制 `scripts/.update-server.env.example` 再填写 `UPDATE_PASS`。

不要把这个文件提交到 git。

### 4.3 自签名证书（已生成，只需备份）

| 文件 | 是否入库 | 作用 |
|---|---|---|
| `scripts/.signing/rebased-codesign.pfx` | 否 | 签名私钥 |
| `scripts/.signing/password.txt` | 否 | pfx 密码 |
| `src-tauri/signing/rebased-codesign.cer` | 是 | 公钥证书，可导入到「受信任的根证书颁发机构」消除未知发布者提示 |
| `src-tauri/signing/thumbprint.txt` | 是 | 证书指纹，编译进客户端用于校验更新包 |

- `scripts/.signing/` **必须备份**。丢失后新包的指纹会变，已安装的客户端会拒绝自动更新，只能让用户手动装一次新版本。
- 换开发机时把 `scripts/.signing/` 整个拷过去即可。
- 只有在确定要换证书时才运行 `.\scripts\signing-cert.ps1 -Force`。
- 签名需要 Windows SDK 里的 `signtool.exe`，`scripts/sign.ps1` 会自动查找。
- 需要时间戳时设置环境变量 `REBASED_TIMESTAMP_URL`（例如 `http://timestamp.digicert.com`），不设置则不加时间戳。

自签名证书不被 Windows 默认信任，手动双击安装时仍可能出现 SmartScreen 提示；自动更新走静默安装，不受影响。

## 5. 发一个新版本（先提交代码，然后跑脚本）

下面用「从 0.1.0 升到 0.1.1」举例。

### 第 1 步：提交代码

先把本次改动 `git commit`。最近一条提交的**标题**会成为给用户看的更新日志，请写清楚。

版本号和更新日志的来源，按优先级：

| 情况 | 版本号 | 更新日志 |
|---|---|---|
| 默认 | 当前版本末位 +1 | 最近一条 git 提交标题 |
| 加 `-Notes "说明"` | 当前版本末位 +1 | `-Notes` 的内容 |
| `update.txt` 最后一行版本已高于当前版本（手写，比如要升 0.2.0） | 用手写的版本 | 用手写的说明 |
| 加 `-NoBump` 或 `-SkipBuild` | 沿用 `update.txt` 最后一行 | 沿用最后一行 |

打包失败后重跑，请加 `-NoBump`，否则版本会再 +1。

### 第 2 步：运行更新脚本

```powershell
cd D:\wwwroot\tauri\rebased
.\scripts\update.ps1
```

也可以：

```powershell
npm run update
```

脚本会按顺序做完这些事：

1. `git fetch` 所有远程，本地落后任何远程就直接停止（避免用旧代码发版）
2. 版本号 +1，读取最近一条 git 提交标题，追加到 `update.txt`
3. 把版本号写入 `Cargo.toml`、`tauri.conf.json`、`package.json`
4. 执行 `npm run tauri build`，通过 `signCommand` 给 `rebased.exe`、卸载程序和 NSIS 安装包签名
5. 上传前校验安装包签名指纹
6. 计算 SHA256，生成 `latest.json`
7. 用 SSH/SFTP 上传安装包并覆盖服务器清单
8. 只提交 `Cargo.toml`、`Cargo.lock`、`tauri.conf.json`、`package.json`、`update.txt`，提交信息为 `chore: 发布版本 x.y.z`，并推送到所有远程（`origin`、`git`）；其它未提交的改动不会被带进去

推送被拒绝时安装包已经发布、版本也已本地提交，按提示 `git pull --rebase` 后手动 `git push` 即可。

成功时终端会打印：

```text
清单地址：http://111.230.247.111/rebased/latest.json
```

不重新打包、把已有安装包重新发布时（不自增版本）：

```powershell
.\scripts\update.ps1 -SkipBuild
```

只要打包、先不上传时（也不会提交推送）：

```powershell
.\scripts\update.ps1 -SkipPublish
```

发布但不提交推送 git 时：

```powershell
.\scripts\update.ps1 -NoGit
```

### 第 3 步：核对服务器清单

浏览器打开：

http://111.230.247.111/rebased/latest.json

确认这 4 项：

| 字段 | 必须满足 |
|---|---|
| `version` | 等于 `update.txt` 里的版本，例如 `0.1.1` |
| `notes` | 等于 `update.txt` 最后一行的更新日志 |
| `url` | 能直接下载到刚才那个 exe |
| `sha256` | 不是空字符串 |
| `silentArgs` | 兼容旧清单保留，客户端不再使用 |

再单独打开 `url` 里的地址，浏览器应开始下载 exe，而不是打开一个网页。

### 第 4 步：用旧版本客户端验证

1. 打开一台仍是旧版本的 Rebased（例如还是 `0.1.0`）
2. 启动后右下角应提示：`发现新版本 0.1.1，正在后台下载并静默安装…`
3. 稍后程序自动退出，没有安装向导弹出
4. 十几秒内 Rebased 自动重新打开
5. **设置 → 关于与更新** 里当前版本应为 `0.1.1`

注意：0.1.27 及更早的客户端仍是旧逻辑（打开安装向导），第一次升级到新逻辑需要用户点一次安装向导，之后的版本才会静默更新。

到这里，这一轮更新才算完成。

## 6. 用户侧实际会发生什么

### 6.1 启动检查

每次启动，程序请求：

```text
GET http://111.230.247.111/rebased/latest.json
```

- 请求失败：静默忽略，不弹窗
- 没有新版本：不提示
- 有新版本：右下角通知并直接开始静默更新；失败时右下角显示失败原因

### 6.2 手动检查 / 安装

路径：**设置（齿轮）→ 关于与更新**

| 按钮 | 作用 |
|---|---|
| 检查更新 | 再拉一次 `latest.json`，对比本地版本 |
| 立即更新 | 仅当检查结果是「有新版本」时可用 |

点「立即更新」后的顺序：

1. 再拉一次清单，确认仍有新版本
2. 按 `url` 下载安装包到系统临时目录
3. 校验 `sha256`；缺失或不一致则中止，不安装
4. 用 `Get-AuthenticodeSignature` 校验签名：状态必须是 `Valid` 或 `UnknownError`（自签名根不受信任时的正常状态），被篡改会是 `HashMismatch`；签名证书指纹必须等于 `src-tauri/signing/thumbprint.txt`
5. 以 `/S /R /UPDATE` 启动安装包：`/S` 静默、`/R` 装完重启应用、`/UPDATE` 保留已有快捷方式
6. 客户端 1.5 秒后自行退出；若仍在运行，安装程序在静默模式下会自动结束它

## 7. latest.json 每个字段的含义

服务器文件：`/usr/share/nginx/html/rebased/latest.json`

```json
{
  "version": "0.1.1",
  "notes": "给用户看的更新说明",
  "url": "http://111.230.247.111/rebased/Rebased_0.1.1_x64-setup.exe",
  "sha256": "安装包的sha256小写十六进制",
  "silentArgs": "/S /R /UPDATE"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `version` | 是 | 新版本号，必须高于用户当前版本 |
| `notes` | 否 | 设置页展示的说明 |
| `url` | 是 | 安装包完整 HTTP 地址 |
| `sha256` | 是 | 缺失时客户端拒绝安装；必须和文件一致 |
| `silentArgs` | 否 | 仅作说明；客户端固定使用 `/S /R /UPDATE` |

发布脚本会自动写这些字段。不要只手改 `version` 却忘了换 `url` / `sha256`。

## 9. 常见失败对照

| 现象 | 原因 | 处理 |
|---|---|---|
| 启动没有任何更新提示 | 清单 version 没有高于本地 version | 先改两个版本号文件，再重新打包发布 |
| 检查更新报「无法连接更新服务器」 | 本机访问不到 `111.230.247.111:80` | 浏览器先打开清单地址确认 |
| 清单打开是网页，不是 JSON | Nginx `/rebased/` 没生效 | 看 `/etc/nginx/conf.d/cng.conf` 是否还有 `location /rebased/` |
| 立即更新报「安装包校验失败」 | 服务器 exe 和清单 sha256 对不上 | 重新跑发布脚本，不要只传 exe |
| 立即更新报「安装包内容为空」 | `url` 下到的不是 exe | 浏览器直接打开 `url` 检查 |
| 点了立即更新，程序退出但没装上 | 安装包不是 NSIS，或被杀毒拦截 | 确认打出来的是 `*-setup.exe`，必要时放行后再装 |
| 提示「安装包签名无效」 | 安装包未签名或被改动 | 用 `update.ps1` 重新打包发布，不要手工替换 exe |
| 提示「签名证书不匹配」 | 用了别的证书签名（例如重新生成过证书） | 恢复备份的 `scripts/.signing/` 后重新打包 |
| 打包时提示找不到签名证书 | 本机没有 `scripts/.signing/` | 从备份恢复，或首次运行 `scripts\signing-cert.ps1` |
| 打包时提示找不到 signtool | 没装 Windows SDK | 安装 Windows 10/11 SDK |
| 发布脚本提示找不到 UPDATE_PASS | 没有 `.update-server.env` | 按第 4.2 节补文件 |
| 发布脚本提示需要 paramiko | Python 没装这个库 | `pip install paramiko` |

## 10. 安全要求

1. 客户端只允许访问 `http://111.230.247.111/rebased/`。
2. SSH 账号和密码只允许出现在本机 `scripts/.update-server.env`。
3. 不要把密码写进 `updater.rs`、前端代码、安装包或 git。
4. 不要把 root 密码发给普通用户。
